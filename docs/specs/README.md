## 规则与证据

- `IC-*`、`IP-*`、`LW-*`、`ED-*`、`WP-*`、`FW-*`、`CC-*` 是稳定规则编号，后续测试、缺陷、提交审查和实现说明应引用对应编号。
- **现状**：已从源码核对的行为。**拟定**：待实现的行为要求。**差距**：现状与拟定规则之间的距离。三者分别记录。
- “已有用例”表示仓库存在对应断言；旧结果只对应当时快照，不把用例存在写成新一轮验收通过。
- 修改规则时同步更新场景、实现位置与差距。实现新行为前先补测试，缺陷先补可复现的失败测试。
- 用例至少检查返回结果、文件、数据库和界面状态；涉及源文件写入时还应检查失败和恢复路径。

## 统一术语

| 名称 | 身份及边界 |
| --- | --- |
| 元件库包 | `component_libraries` 中的 UUID，组织符号根目录、封装根目录和可选 3D 根目录 |
| 符号子库 | 一个实际 `.kicad_sym` 文件；可为空、尚未登记，不能假定始终有数据库 UUID |
| 符号 / 封装 | 已登记对象按数据库 UUID 识别；名称用于显示，不能用于消除同名歧义 |
| 来源 | 规范化物理路径 `source_key`；导入同一来源时用于保持对象身份 |
| 任务 | `task_id` 对应本次异步执行及进度；终态记录受数量和进程生命周期限制 |
| 确认意图 | 一次确定的目标和选择，使用 `operation_id` 幂等重试；不是 `task_id` |
| 提交后刷新 | 重新读取列表、库及状态；失败不表示文件/数据库提交被撤销 |
| 撤销 | 用户主动撤回一次已完成编辑；与取消在途任务、故障回滚、启动恢复分别定义 |

## 当前源码与既有决定的差异

上一轮用户确认保留删除旧 `POST /api/plugins/execute`。本轮读取的 [routes.cpp](../../src/interface/api/routes.cpp) 又包含该路由，相关 API 文字也发生变化。这是工作区与上一轮验收快照的差异，本轮没有改动或恢复该入口。

本组规格的新增调用统一以 SDK 任务接口和 `/api/tasks` 为规范入口；旧路由不作为新功能依赖。旧入口的最终移除应单独核对修改来源并验收，不能用规格文字掩盖当前代码的存在。

## 共同约束

- 使用现有任务服务、数据库 session、源文件 mutation 和前端模型；不另建轮询体系或绕过宿主直接写用户库。
- 不以名称、列表索引或路径字符串前缀替代对象身份和目录归属校验。
- 不把批量导入描述成全局原子操作；每项功能须说明实际提交单元、部分失败和可重试范围。
- 性能要求使用有界并发、消息、剪贴板和历史记录；编辑命令的数值上限见 [EDITING_COMMANDS.md](EDITING_COMMANDS.md) 的「对象编辑契约」，测量与验收证据见 AgentDocs 最终报告。
