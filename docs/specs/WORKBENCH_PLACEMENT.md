# 工作台与内置插件界面位置

决策日期：2026-10-20（Asia/Shanghai）。依据：用户明确要求「目前的内置插件 LCSC、Git 只放在最左边的侧边栏里」。本文件记录产品位置约束；实现差距与修复验收放在 `docs/AgentDocs/`。

## 内置插件的位置规则

| 编号 | 稳定规则 |
| --- | --- |
| WP-001 | 当前内置 LCSC 导入与 Git 版本管理只在工作台最左侧侧边栏提供业务界面。最左侧侧边栏指左侧活动图标栏及其相邻、展开的主侧栏面板，不指右侧 Inspector。 |
| WP-002 | LCSC、Git 各使用一个活动栏入口和对应 `sidebar.panel`；完整交互在各自侧栏面板完成。不得只保留侧栏摘要，再要求用户打开中心详情页。 |
| WP-003 | 两个内置插件不注册自身的 `app.view` 中心页；不在首页工具栏、右侧 Inspector、侧栏底部“插件视图”列表或其它区域增加重复业务入口。通用插件管理中的启停配置仍属于宿主设置。 |
| WP-004 | LCSC 的查号、目标包、符号子库、封装选择、确认、提交结果与继续导入均在其侧栏面板呈现，保留 LW/IP 规格的显式选择、幂等和提交后刷新规则。 |
| WP-005 | Git 的元件库/仓库选择、更改列表、提交消息、状态、历史、差异、初始化和任务取消均在其侧栏面板呈现；长内容使用面板内分区、页签或滚动，不迁往中心页。 |
| WP-006 | 普通侧栏切换仅改变展示，不重建业务模型、不重发已经确认的写操作、不丢弃输入，不取消后台任务。重新打开显示同一模型状态；停用与销毁仍按现有插件生命周期释放。 |
| WP-007 | 主侧栏可按工作台既有机制调宽、折叠及在窄窗以左侧抽屉呈现。适配宽度通过面板内布局和独立滚动完成，不借窄窗适配创建中心或右侧的替代入口。 |
| WP-008 | 宿主公共状态栏/任务面板可显示通用任务状态与错误摘要，不能承载两个插件的专属表单、差异查看器或中心详情跳转入口。 |
| WP-009 | 本约束限定当前两个内置插件，不撤销第三方插件的通用 `app.view`/七插槽契约。位置调整在各插件贡献与布局适配内完成，不在宿主中按插件名硬编码业务流程。 |

## 与旧设计的关系

本决策取代 `docs/AgentDocs/WORKBENCH_LAYOUT_PLAN_2026-10-19.md` 第 13.5 节对 LCSC、Git 的“侧栏摘要 + 中心详情”安排，仅覆盖这两个内置插件的位置。既有工作台分栏、中心页面、公共插件 SDK 与 LW/IP/ED 行为约束继续适用。历史实施记录保留原貌，不反写为当时已经满足本决策。

位置迁移必须移除两个插件的中心 view 注册和摘要中的“打开详情”跳转，处理已保存布局中的旧插件页签。使用既有缺失贡献清理和布局恢复机制，保留其余页面与尺寸，不通过重置全部布局完成迁移。

## 验收场景

| 场景 | 必须观察的结果 |
| --- | --- |
| 左侧点击 LCSC / Git 图标 | 完整界面出现在主侧栏，中心活动页和页签数不变 |
| 查看 Git 历史/差异，完成 LCSC 查号与导入 | 所有业务步骤在当前侧栏内可达，无中心详情入口 |
| 两个内置插件启用、停用与重新启用 | 无重复入口，第三方贡献仍正常，生命周期与模型状态符合原有契约 |
| 存在旧 `lcsc-details` / `git-details` 的布局后重启 | 旧页签被清理，其余页签、分组和布局尺寸保留 |
| 工作空间/LCSC/Git 往返切换，后台导入或提交在途 | 同一任务/operation_id 继续，不重复写入，草稿与进度可恢复查看 |
| 亮/暗、中/英、1920/1280/960/800/600 宽度及拖动侧栏 | 无横向挤出、按钮与长内容可达；窄窗只通过左侧抽屉打开 |
